# 目录搬家助手

Windows 10/11 本地小工具，使用系统自带的 Robocopy 和 .NET Framework 4.8。无需 Python、Node.js 或联网。

## 启动

便携包解压后双击 `目录搬家助手.exe`。请将旁边的 `目录搬家助手.exe.config` 一起保留，以支持长路径。源码仓库不包含 EXE，克隆源码后请先按下方步骤构建。

## 复制与核对

1. 选择整个文件夹，或选择同一目录下的多个文件。
2. 填写目标目录。复制的是源目录**内部内容**；如想保留源文件夹名，把它加到目标目录末尾。
3. 默认 8 线程，复制后按大小、时间等信息核对。可选择 SHA-256 逐文件内容校验，速度较慢。
4. 默认更新不同的同名文件；勾选“保留目标已有文件”可避免覆盖，但核对可能发现差异。
5. 源文件和目标多余文件均保留。不使用 `/MIR`、`/MOVE` 或自动删除源目录。
6. 停止后可以再次开始，相同文件会被跳过。大文件需要字节级续传时勾选“大文件断点续传”，可能降低小文件复制速度。

进度条仅表示任务正在执行，不伪造整体百分比。当前记录和原始 Robocopy 日志可通过“打开日志”查看。应用只解析中文、英文 Robocopy 末尾统计；其他系统语言不会误报成功。

链接单独处理，不展开重复复制。整个项目内的链接可自动改为目标项目内对应位置。无法映射的外部依赖、失效链接、无法读取的目录都会列为未完成项。

## 搬盘后的失效链接修复

在“链接修复”页面填写：

- **原目录（可空）**：旧目录还在时填写，用它找回已经被复制为空目录的链接。
- **待修复目录**：新盘上的目录。
- **旧项目根目录**：例如 `C:\Projects\ExampleProject`。
- **新项目根目录**：例如 `F:\Projects\ExampleProject`。

即使只复制了 `output` 或 `tmp` 子目录，旧、新项目根目录仍应填写完整项目根目录，以便正确映射项目依赖。

点击“扫描链接”，核对清单，勾选需要修复的项目，再点“修复勾选的链接”。支持 NTFS 目录联接（Junction）及文件/目录符号链接。目录联接通常不需要管理员；符号链接可能需要 Windows 开发者模式或管理员权限。

修复只会创建缺失的链接，或替换旧链接、空目录。绝不替换真实文件或非空目录。新目标不存在、循环链接、父目录经由其他链接或路径冲突时拒绝操作；创建失败会尝试恢复旧链接/空目录。每次修复保存路径、旧目标、新目标和执行结果。

只扫描新目录时，无法凭空判断某个普通空目录曾经是否为链接；应保留旧目录直到扫描完成。外部依赖不自动猜测目标。云端占位文件等未知重解析点不会当成普通链接修复，请先下载到本地。

## 权限、日志与检查边界

访问失败时可点“以管理员身份重开”。管理员复制/核对使用备份读取模式，工具不会更改源目录访问权限。仍然无法枚举的目录不会被忽略，任务不会显示完整核对通过。

日志和路径设置保存在 `%LOCALAPPDATA%\FolderBridge`。程序不上传任何文件或日志。

文件核对不等于项目运行测试。链接目标内容不会被重复展开校验；共享依赖应位于新项目内并已单独复制。Python 虚拟环境、启动脚本、Codex 工作目录等可能含绝对路径，需另行处理。支持内容、普通属性和时间迁移，不声称完整克隆 NTFS ACL、所有者或应用配置。

## 从源码编译与验证

在 PowerShell 7 中运行 `./build.ps1`。使用 Windows 自带的 .NET Framework C# 编译器。

可用 `目录搬家助手.exe --self-test <测试目录>` 执行真实文件系统和 Robocopy 集成测试。测试仅在指定测试目录下新建随机子目录，不清理或使用个人项目。结果写入 `test-results.txt`。

技术依据：[微软 Robocopy 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy)。

## 打包与隐私

运行 `./package.ps1`，通过集成测试后，在 `release/public/` 下的新目录生成源码 ZIP、Windows 便携 ZIP 和 SHA-256 摘要。脚本只打包明确清单内的文件；不包含旧测试目录、截图、日志、路径设置或个人文件。文件符号链接测试因权限不足跳过时会明确显示。

路径设置和日志是本机私人数据，不随源码或便携包发布。分享日志前请先移除个人路径，详见 [安全与隐私](SECURITY.md) 和 [发布检查记录](RELEASE-CHECK.md)。
